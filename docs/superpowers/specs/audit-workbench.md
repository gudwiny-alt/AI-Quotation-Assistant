# 稽核审查工作台需求说明书

版本 V1.0 · 2026年9月13日

## 一 目标与范围

本模块面向产品经理，对本批次商品、渠道价格、截图证据和最终报价工作簿进行稽核。工作台需同时展示全批次检查概况、单品检查结果和具体检查依据，帮助用户定位问题、补充材料并确认可报送的最终版本。

界面统一使用“未通过”表示已确认不符合必需规则的结果。“未通过”限制最终报送确认，但不停止程序运行，不妨碍查看证据、修改数据、保存草稿和重新核验。

本次交付范围为需求说明书及更新后的界面设计图。后续开发沿用现有取价、截图和报价生成流程；报价决策模块负责填写与试算，稽核模块负责核对最终数据及证据，两者共享同一套业务规则。

## 二 页面结构与统计口径

### 同一工作台内完成逐层查看

| 区域 | 展示内容与交互 |
| --- | --- |
| 顶部汇总 | 展示本批次商品数、检查记录数、通过数和需处理数。存在未检查项目时必须显示，不能遗漏后仍提示全部通过。 |
| 六类检查入口 | 每类展示全批次通过、未通过、待复核、待补充数量；零值可省略。统计不随当前选中机型、分页或异常筛选变化。 |
| 左侧商品稽核清单 | 按商品记录汇总，一条商品规格记录一行。展示品牌机型、规格、各状态数量和综合状态；支持全部商品与异常待办切换。 |
| 右上单品稽核结果 | 展示选中商品的适用稽核点、检查摘要和结果。通过项同样可查看；长清单可滚动，关键标题与商品信息保持可见。 |
| 右下检查依据与处理 | 点击稽核点后展开对应对照数据、判断原因、截图或表格定位，以及补充、修正、复核操作。 |
| 底部报送状态 | 显示尚未解决的问题和是否可确认最终报送版；保留导出草稿入口。 |

以上区域处于同一工作台，不新增强制跳转的单品子页面。原始截图可打开大图；查看取价记录或修正报价可进入现有对应模块，返回后保留批次和商品定位。

### 筛选与联动

默认检查类别为全部。点击某类入口后，左侧按该类别展示商品及检查汇总，并明确标注当前范围；选中商品后，右侧默认展示同一类别的检查，提供“查看该商品全部检查”入口。切换为全部检查时要同步更新范围标识，避免误认筛选结果就是全量结果。

异常与待办显示存在未通过、待复核、待补充或未检查事项的商品。选择某商品不会改变顶部和六类入口的全批次统计；翻页也不改变全量统计。

### 统计定义

商品以可区分型号、内存、容量、颜色及业务编码的稳定记录为单位，不能只用型号文字合并不同规格。检查以“批次＋商品记录＋规则＋必要的渠道或证据对象”为单位，复核更新当前结果，历史执行另行留存，避免每次重检使检查数量膨胀。

同一检查记录只归属一个主分类，避免重复计数。需处理数＝未通过＋待复核＋待补充；未检查和不适用另列，不适用不计为通过。图示场景中所有检查已执行且均适用，因此60＝54＋2＋4。

## 三 状态含义与确认条件

| 状态 | 判定含义 | 处理方式 |
| --- | --- | --- |
| 通过 | 已取得充分依据，符合本项规则。 | 保留判断数据、依据和检查时间；数据变更后重新核验。 |
| 未通过 | 已经确认违反必须满足的要求。 | 修正问题并重新核验；不能直接点击“通过”绕开硬性规则。 |
| 待复核 | 当前依据或识别结果不足以确定结论。 | 人工核对原始证据，填写结论及理由后完成复核。 |
| 待补充 | 缺少必要数据、截图、备注或依据附件。 | 补齐材料后重新执行受影响检查。 |
| 未检查 | 尚未执行、检查失败或数据变更后待重检。 | 执行或重试；技术失败需显示具体原因，不等同于业务不合规。 |
| 不适用 | 本项规则不适用于该商品或当前场景。 | 记录明确的适用性判断依据，不得用于掩盖缺失数据。 |

执行中的检查可临时显示“检查中”，在汇总中仍归入尚未完成，不得作为通过或从应检查数量中消失。所有状态同时使用文字与颜色表达。

### 商品综合状态

仅有未通过问题时，商品综合状态为“未通过”；同时存在多类问题时可汇总为“需处理”，但必须在同一行明确列出未通过与待处理数量。其他情况按待补充、待复核、未检查提示。仅当全部必需且适用的检查完成并通过，才可显示“全部通过”。非报价商品的处理状态单独展示。

### 最终报送确认

仅当本批次拟报送记录的所有必需检查均已完成、不存在未通过或未解决的待处理事项、最新工作簿与证据版本均已核验时，才启用“确认最终报送版”。切换筛选、隐藏异常或选择单品，不能改变该全批次判断。

确认属于优福包而列入“不报价”的商品保留原因与确认记录，检查其是否按要求从拟报送报价范围排除或标明不报价。其价格检查可按明确适用条件处理，但不能直接删除商品或一律标为通过。

### 人工复核边界

文件是否存在、数值是否超限、写回值是否一致等采用确定性检查。截图识别仅辅助判断；无法确认的规格、优惠条件或被遮挡信息进入待复核。人工处理记录应包含处理人标识、处理时间、结论、理由及证据版本；无法可靠获取身份时，不伪造登录身份。

人工可确认识别疑点或适用性，但不得把已证实超出手机4.5%上限等硬性违规直接改为通过。调价例外只按已确认的业务例外流程处理。

## 四 商品渠道与截图检查目录

以下目录将已讨论的六类检查细化为开发检查点。每项需有明确输入、适用条件、比较依据和结果；规则未定义或输入缺失时，不得默认通过。

### A 商品分类与关联

| 编号 | 检查点 | 核验重点 |
| --- | --- | --- |
| A01 | 商品分类 | 手机、多形态等分类与基础商品信息一致；类别不明时需核实，不能套用错误加价规则。 |
| A02 | 规格一致 | 品牌、型号、内存、容量、颜色在基础表、营销商品及资源数据之间是否对应。 |
| A03 | 关联准确 | 依据编码及规格匹配业务记录；零匹配、冲突候选需单独处理。允许的一对多关系按业务定义判断。 |
| A04 | 重复与漏项 | 相同业务商品是否被重复生成、错误合并或遗漏；不同规格不能按相同名称合并。 |

### B 渠道与价格口径

| 编号 | 检查点 | 核验重点 |
| --- | --- | --- |
| B01 | 渠道与店铺 | 品牌官网、京东自营或规定官方旗舰店、天猫官方旗舰店等是否满足来源要求。 |
| B02 | 报价对象 | 价格是否对应当前所选商品规格；缺货、下架或错误商品页不能作正常有效报价。 |
| B03 | 优惠条件 | 区分普通价与补贴、以旧换新、分期、会员或其他有条件价格；接受口径未明确时待复核。 |
| B04 | 最低有效价 | 只在满足资格与口径的有效记录中比较；所选价格应关联来源、取价时间及证据，不以0代替缺失价格。 |

### C 截图内容核验

| 编号 | 检查点 | 核验重点 |
| --- | --- | --- |
| C01 | 页面内容 | 识别登录、验证码、错误、空白等页面；截图保存成功不能代表页面内容正确。 |
| C02 | 规格对照 | 将截图中的型号、内存、容量、颜色与目标商品对照；识别不确定时待复核。 |
| C03 | 价格与店铺 | 截图能否支持记录中的价格及渠道店铺，优惠条件是否可辨认。 |
| C04 | 可读与完整 | 关键规格、价格、来源是否被裁切、遮挡或模糊；原图应可打开查看。 |

## 五 完整性报价与报表检查目录

### D 证据与数据完整性

D01 应有记录：按本批次应执行的商品和渠道检查结果覆盖情况。渠道不可售或不适用应有明确原因；不能一律要求三张成功截图，也不能把技术失败当作正常结束。

D02 文件有效：证据存在、非空、可读取；截图路径与实际文件对应，损坏或缺失需待补充。D03 关联完整：商品、渠道、价格和截图形成可追溯关系，检查重复使用证据、错挂商品和混用批次。D04 数据版本：报价月份、取价时间、附件及数据来源版本可定位；证据有效期限另按确认规则配置。

### E 报价规则与资格

| 编号 | 检查点 | 必须遵循的口径 |
| --- | --- | --- |
| E01 | 采购价与均价 | 终端公司采购价≤全国比价系统均价；不是将当月结算报价直接与全国均价比较。 |
| E02 | 手机加价率 | 当月铺货结算报价≤采购价×1.045；精确数值判断，显示舍入不得放行超限。采购价缺失或无效需处理。 |
| E03 | 历史报价 | 当月报价不得高于适用往期报价；历史范围与来源在实现前明确。 |
| E04 | 零售与一级库 | 当月报价不得高于分销零售价、一级库价格及规定渠道的有效官方零售价。 |
| E05 | 在库资格 | 报送终端必须一级库在库；仅有编码或能关联到历史记录不等于当前在库。 |
| E06 | 优福包确认 | 入总部一级库超过14个月先确认优福包属性；确认属于后正式列入不报价，确认不属于继续其他检查。 |
| E07 | 调价与依据 | 首次报价起原则上6个月下调5%、12个月下调10%；无法调价需合理依据、AO备注和关联材料。 |

渠道买断价负责核对填写与写回，尚不增加独立硬性价格上限。多形态5%口径、调价基准及超过12个月后的算法见待明确事项，不在实现时擅自推定。

### F 报表与报送一致性

F01 写回定位：按稳定商品记录核对工作簿页签和行，防止错行、漏填或覆盖其他商品。F02 值一致：核对K当月报价、L采购价、M全国均价、P买断价、Q零售价及AO备注，列映射以实际模板为准。

F03 公式与结构：原有公式、自动生成字段和模板结构保持正确；公式结构校验与实际计算结果核验分别记录，无法计算不能宣称结果已核验。F04 输出范围：检查不报价处理、草稿和最终版本标识。F05 最新版本：报价、证据或工作簿修改后，原检查结论不得继续充当最终确认依据。

## 六 处理流程数据与输出

### 从执行完成到最终确认

1 完成现有取价与报价生成后，读取本批次商品、来源、截图、执行结果及工作簿。产品经理补齐手工价格后，执行与其相关的报价稽核；未补齐时明确待补充。

2 生成检查记录并按六类汇总。左侧选择商品，右侧查看全部适用稽核点；点击检查项，展开对照和依据。不得用概念图中的固定数量或预设通过状态代替真实检查。

3 根据问题提供对应操作：数据错误返回数据准备或报价填写；取价错误查看原取价记录并按现有流程修正；证据缺失补充或重新采集；识别疑点进行人工复核。不得由稽核按钮直接无提示触发整批取价。

4 修正或补充后，重新核验受影响项目并更新单品、分类、全批次统计。涉及最低有效价、报价上限、写回和最终报送的下游检查一并失效并重检。

5 全批次达到确认条件后，重新读取最新输出并确认最终报送版。此按钮仅生成和标记本地最终版本，不自动上传外部系统或向他人发送材料。

### 检查记录与追溯信息

| 数据组 | 至少记录的内容 |
| --- | --- |
| 定位 | 批次、报价月份、商品稳定标识、规格、规则编号、主分类；必要时关联渠道和具体证据对象。 |
| 判断 | 输入值、比较依据、适用性、结果、原因、自动或人工检查方式、执行时间、规则版本。 |
| 证据 | 源文件、工作表及行列定位、渠道链接、取价时间、截图和附件位置、被核验的数据或文件版本。 |
| 处理 | 处理前后结果、原因、材料、处理人标识与时间、重新检查记录、最终确认对应的输出版本。 |

### 保存与输出

稽核报告应包含批次范围、六类及单品汇总、全部检查结果、异常依据、人工处理记录和未解决事项。导出草稿允许存在问题，但必须标明待处理情况；最终版本与草稿应明确区分。

稽核报告采用独立本地文件，不覆盖原报价工作簿。业务数据修正仍通过既有写回入口定位原工作簿。保存需保留可恢复的上一版，写入失败不得更新成已保存或已通过。报告文件格式在开发前明确。

数据及附件保存在现有本地工作目录。稽核页面展示和浏览本地证据不应额外启动浏览器采集；图像识别若需外部服务，其数据范围、成本和失败降级方式另行确认。

## 七 验收要点与待明确事项

| 编号 | 验收场景 | 预期结果 |
| --- | --- | --- |
| T01 | 统一状态文案 | 本模块统计、列表、详情、提示和导出报告统一使用“未通过”，不再使用旧称。 |
| T02 | 全批次与单品联动 | 选中商品只更新单品区域；分类汇总保持全批次口径，切换筛选后明确显示范围。 |
| T03 | 同机型多个检查 | 左侧一条商品规格记录一行，右侧可查看其全部检查项，点击不同项能看到相应依据。 |
| T04 | 统计守恒 | 分类总数与全批次总数一致；复核不重复增加检查数，不适用及未检查不计为通过。 |
| T05 | 文件存在但规格可疑 | 文件完整性可通过；截图内容保持待复核，不能因文件存在自动判内容合格。 |
| T06 | 精确报价边界 | 手机采购价2000、报价2090不因加价率失败；2090.0001必须未通过，不以显示舍入放行。 |
| T07 | 超14个月确认 | 未确认优福包时待复核；确认属于后记录不报价；确认不属于后继续其他资格与价格检查。 |
| T08 | 变更和异常恢复 | 修改价格或证据使相关旧结论失效；检查或保存失败可重试，保留已保存数据和真实错误原因。 |
| T09 | 最终确认条件 | 未通过、必需待处理或未检查事项未解决时禁止最终确认；导出草稿仍可用。 |
| T10 | 回归与界面操作 | 既有取价截图流程保持可用；长列表鼠标滚轮可滚动，金额不换行，状态和按钮不被截断。 |

### 实现前需明确的业务口径

以下细节属于待明确事项，不影响本稿记录已确认的界面与状态要求；在细节确定前，相关检查不能凭推测自动通过。

• 往期报价取上一期还是所有往期最低值，以及对应历史来源。
• 首次报价及入库、库存字段来源；6个月和12个月调价基准、超过12个月后的算法与例外确认方式。
• 多形态产品5%规则的适用分类；各渠道优惠价格接受条件、证据有效期限和可接受缺项原因。
• 工作簿实际列映射、公式计算方式、不报价在最终表中的表达；稽核报告格式与附件组织方式。
• 图像识别采用本地或外部方案、人工复核入口与记录方式。

### 关联需求与版本说明

本说明书与《2026-09-13 报价决策智能体优化 已确认》配套使用。报价填写与稽核共用价格规则及数据来源；若规则后续调整，应同步更新两个模块与对应验收用例。V1.0已纳入全批次分类统计、按商品汇总、单品检查集合、检查依据展开及“未通过”统一文案。
