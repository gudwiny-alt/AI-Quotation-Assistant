# 华为官网真实闭环设计

日期：2026-08-12  
前置基线：荣耀、小米、OPPO、vivo 官网已通过 Mac 真站验收并冻结。

## 1. 目标

为系统规范品牌“华为”增加华为商城的真实查价与截图闭环：按基础表顺序读取每一条华为记录，搜索精确基础机型，进入华为商城正式商品详情页，选择目标容量和颜色，提取官网有效价格，生成正式整屏截图，并写入报价表 `AK` 和 `AN`。

首轮验收使用现有 7 条基础表中的华为行：`华为畅享 90 Pro Max / 8GB+256GB / 曜金黑`。如果华为商城确实没有该精确机型，应按合法“无机型”完成；同时必须再用一条商城当前在售华为手机完成正常价格与截图闭环，证明正常路径可用。

## 2. 需求依据

原始需求和用户确认的华为官网规则如下：

- 入口：`https://www.vmall.com/`；
- 从华为商城真实搜索结果进入精确基础机型的正式商品详情页；
- 商品卡是否缺货不阻拦进入详情页；
- 优先精确匹配 `RAM＋存储容量`，页面只提供存储容量维度时允许精确匹配存储容量；然后精确选择颜色；
- 同一目标配置出现多个有效当前售价时取最低值；
- 排除划线原价、优惠券、补贴、以旧换新、分期月供、保险、配件和其他配置的价格；
- 正常报价截图只要求同屏证明产品名称、采用价格、目标容量和目标颜色。

用户于 2026-08-12 确认采用“华为独立适配器”方案，并确认上述最低有效当前售价口径。

## 3. 范围与冻结边界

本轮只新增华为官网独立适配器、华为真实结构 fixture、契约与集成测试、品牌注册和华为单站验收所需的最小入口：

- 不修改荣耀、小米、OPPO、vivo 的页面业务逻辑；
- 不修改京东、天猫；
- 不修改 Excel 字段映射、公式或三表关联；
- 不把华为 DOM 条件写入通用官网适配器；
- 不恢复或重排已冻结站点的截图步骤；
- 华为真站验收通过并冻结后，才进入苹果官网开发。

若确需调整公共机械运行层，只允许追加华为注册或复用既有接口，并必须通过冻结站点回归。

## 4. 方案选择

### 方案 A：华为独立适配器，共用机械运行边界

采用。复用现有 `LiveOfficialAdapterBase` 的批准域名、检查点、正式截图、缩放恢复和任务恢复接口；搜索、商品卡、详情身份、容量策略、颜色、价格候选和截图视图全部封装在 `official_brands/huawei.py`。

### 方案 B：继续使用通用官网占位适配器

改动较少，但不能可靠表达 VMALL 搜索、双详情路径、容量维度和价格污染边界，容易出现过早结束或误价。不采用。

### 方案 C：根据机型名拼接详情 URL

步骤较少，但无法证明真实商品身份，也不能处理商品 ID、相似机型和页面迁移。不采用。

## 5. 批准域名与页面身份

### 5.1 批准入口与搜索页

- 商城入口为 `https://www.vmall.com/`；
- 只接受华为商城批准的 HTTPS 主机和搜索路径；
- 搜索提交后必须有界等待真实结果区域完成，普通“正在加载”不立即判失败；
- 登录、验证或明确风控页按现有人工暂停与继续机制处理，不写合法“无”。

### 5.2 正式详情页

接受 VMALL 当前真实存在的两类数字商品身份：

- `/product/<数字>.html`；
- `/product/comdetail/index.html?...prdId=<数字>`。

可以带 `cid`、`prdId`、`sbomCode` 等华为商城真实查询参数，但不得接受非 VMALL 主机、无数字商品 ID 的任意页面或根据机型名猜测的 URL。

从检查点恢复时，必须在导航前验证结果类型和详情 URL；价格成功、无容量或无颜色只允许恢复至已批准的数字商品详情页，无机型只允许恢复至已批准的搜索结果页。

## 6. 搜索与商品卡选择

1. 打开华为商城入口，等待真实搜索入口可交互。
2. 输入基础表市场通俗名称并提交一次搜索。
3. 在具体搜索结果容器中按规范化基础机型精确匹配可见商品卡。
4. 商品卡无需预先匹配目标颜色或容量；同一精确基础机型可进入第一个合法正式详情链接，再在详情页选择配置。
5. “缺货”“暂时缺货”“到货通知”不阻拦进入详情页。
6. 第一张精确商品卡 URL 非法时继续检查后续精确卡；只有所有精确卡 URL 都非法时才技术失败。
7. 排除保护壳、保护膜、充电器、耳机、支架、适用配件，以及 Pro、Pro+、Plus、Ultra、Max、青春版、优享版等与目标基础机型不同的派生型号。
8. 搜索页短暂出现空态不能提前写“无机型”；必须完成约 10 秒的有界完整窗口。窗口内晚到的精确卡优先，完整窗口结束仍无精确卡才成立合法“无机型”。
9. 进入详情页后以最终 URL 和产品标题重新验证商品身份，不继续读取旧搜索页状态。

## 7. 配置选择

### 7.1 容量策略

1. 优先寻找包含完整 `RAM＋存储容量` 的版本组，例如 `12GB+256GB`；
2. 如果该详情页的配置维度只展示存储容量，例如 `256GB`，允许使用基础表目标存储容量做精确匹配；
3. 如果页面同时提供完整 `RAM＋存储容量`，不得退化为仅存储匹配；
4. 已经唯一选中的精确目标选项不重复点击；
5. 商品整体缺货不等同于目标容量不可用；只要目标选项可识别、可选择或已选中，就继续正常报价；
6. 容量组选项短暂未加载时，在约 5 秒有界窗口内等待，完整窗口结束后才能成立合法“无容量”。

### 7.2 颜色

1. 容量确认后精确匹配基础表目标颜色；
2. 已经唯一选中的精确目标颜色不重复点击；
3. 商品整体缺货不阻拦颜色选择；
4. 颜色组选项短暂未加载时，在约 5 秒有界窗口内等待，完整窗口结束后才能成立合法“无颜色”。

若配置点击后产品标题、商品 ID 或选择组发生漂移，必须封闭失败，不得使用其他配置价格。

## 8. 价格规则

价格候选必须属于当前 VMALL 数字商品详情页、当前已选容量与颜色的主购买摘要。候选应是可见人民币整机当前售价，并排除：

- 划线原价或市场参考价；
- 优惠券、领券后价、满减、直降金额本身；
- 国家补贴、平台补贴、会员补贴等优惠条件价；
- 以旧换新补贴；
- 分期月供、利息；
- 保险、延保、服务、配件和推荐商品金额；
- 非目标配置或其他机型价格。

对剩余有效当前售价取最低值。示例：目标配置页面显示当前售价 `4999`、划线原价 `6499`，写入 `4999`。

价格确认必须满足：

1. 产品标题、数字商品身份、容量和颜色仍与目标一致；
2. 价格短暂缺失时在统一约 5 秒窗口内重试，不立即失败；
3. 有效价格须连续稳定约 3 秒；
4. 价格候选歧义、配置漂移、URL 漂移或安全页不得被价格重试吞掉；
5. 价格稳定后立即原子保存价格、详情 URL 和检查点，再进入正式截图。

## 9. 截图视图

### 9.1 正常报价

正常报价的网页业务证据只有四项：

1. 精确产品名称；
2. 最终采用的官网价格；
3. 目标容量；
4. 目标颜色。

截图准备顺序：

1. 进入详情页并完成配置、价格稳定后，重新读取四项；
2. 四项在当前视口中同时、稳定、清晰可见，且中心未被浮层遮挡时立即截图，不滚动、不缩放；
3. 否则幂等切换至 80% 并重新读取；已经是 80% 时不重复写入；
4. 80% 后四项同屏则立即截图；
5. 仍不同屏或任一证据被浮层遮挡时，最多进行一次由四项真实矩形和遮挡关系计算的轻微定向滚动，滚动绝对距离不超过 160 像素；
6. 定位后重新获取四个真实节点、文字、矩形和中心命中状态，满足即截图，仍不满足则封闭失败；
7. 不删除、隐藏或修改华为页面浮层 DOM；
8. 库存、收货地区、促销、购买按钮、服务、销售类型、处理器、套餐和固定父级层级不是第五项门槛。

浏览器地址栏和 macOS 日期时间自然保留在整屏证据中，不增加网页业务条件。

### 9.2 合法“无”

- 无机型：搜索词与具体搜索结果区域同屏；
- 无容量：产品信息与完整容量/版本选项区域同屏；
- 无颜色：产品信息与完整颜色选项区域同屏。

合法“无”截图也必须取最终稳定视图；若网页仍在加载或证据节点短暂缺失，应在相应有界窗口内等待，而不是提前截图。

## 10. 保存、恢复与多行执行

- 严格按基础表中全部华为行的原顺序逐条处理；
- 每行价格确认后立即保存 `AK`、详情 URL 和检查点，再处理截图；
- 截图成功后保存 `AN`，然后开始下一行；
- 截图失败只令 `AN` 为空，不得清空已保存的 `AK`；
- 从详情检查点恢复时直接打开已批准详情 URL，不重新搜索；
- 从搜索结果检查点恢复合法“无机型”时，不得跳到其他机型；
- 运行中单行技术失败不阻止后续华为行执行；
- 最终报价表、执行报告、成功/部分成功/失败统计必须与逐行检查点一致。

## 11. 组件边界

### 11.1 华为独立适配器

`src/quote_app/sites/official_brands/huawei.py` 负责：

- VMALL 搜索和结果完整窗口；
- 商品卡精确匹配和 URL 选择；
- 数字商品详情身份验证；
- `RAM＋存储` 或仅存储容量策略；
- 颜色选择；
- 主售价候选过滤和最低价；
- 四证据读取、80% 视图和一次轻微定位；
- 截图前后的业务状态复核。

### 11.2 公共层

公共层只承担批准主机、任务观察结果、检查点、正式截图请求、缩放恢复和运行调度等机械接口。华为选择器、价格语义和配置策略不得泄漏到公共层。

### 11.3 注册层

品牌工厂仅将系统规范品牌“华为”分派至 `HuaweiOfficialAdapter`。其他品牌映射保持字节级或行为级冻结。

## 12. 错误处理

以下属于合法业务结果，可写“无”并生成证据：

- 完整等待后无精确机型；
- 详情身份正确但完整等待后无目标容量；
- 容量正确但完整等待后无目标颜色。

以下属于技术失败，不得写合法“无”：

- 登录、验证码、安全验证或风控；
- 搜索提交失败、页面仍在加载或结果容器不可识别；
- 所有精确商品卡 URL 非法；
- 详情 URL、标题或配置身份漂移；
- 主价格歧义、价格结构污染或稳定窗口失败；
- 四证据节点、矩形或中心命中状态无法可靠获取；
- 正式截图权限或系统截图失败。

技术失败必须在执行报告中记录明确阶段和原因，便于后续优化。

## 13. 测试与验收

契约和集成测试至少覆盖：

1. 华为精确机型正常报价；
2. 两类正式数字商品详情 URL；
3. 搜索晚到精确卡、早期空态和完整窗口无机型；
4. 相似派生机型与配件不得误入；
5. 第一张精确卡 URL 非法、后续合法卡可进入；
6. 缺货卡仍进入详情；
7. 完整 `RAM＋存储` 精确匹配；
8. 页面仅提供存储时的精确存储回退；
9. 页面提供完整版本时禁止仅存储回退；
10. 容量与颜色晚到、合法“无容量”和合法“无颜色”；
11. 多价格污染下取当前主商品有效最低价；
12. 价格暂缺恢复、连续稳定、配置或 URL 漂移失败；
13. 四项同屏立即截图；
14. 需要时幂等 80%＋至多一次不超过 160 像素的定向滚动；
15. 浮层遮挡任一证据时正确定位，持续遮挡则失败；
16. 截图失败保留价格和详情 URL；
17. 两行按基础表顺序写入 `AK`、`AN`，报告统计一致；
18. 重启从详情检查点恢复，不重新搜索；
19. 荣耀、小米、OPPO、vivo、京东、天猫、Excel 和 macOS 正式截图运行时冻结回归通过。

Mac 真站验收分两步：

1. 使用现有基础表华为行 `华为畅享 90 Pro Max / 8GB+256GB / 曜金黑` 验证真实结果；若无精确商品，必须正确生成合法无机型证据；
2. 使用一条 VMALL 当前在售手机验证精确配置、最低有效价格、80%/定位策略、正式截图以及 `AK`、`AN` 完整写入。

只有代码测试通过且用户完成真站验收，华为官网才标记为冻结。

## 14. 完成定义

华为官网开发完成必须同时满足：

- 能从真实搜索进入精确 VMALL 数字商品详情页；
- 容量策略和颜色选择正确；
- 价格符合最低有效当前售价规则；
- 正常或合法“无”截图清晰且证据完整；
- 价格和截图分别写入 `AK`、`AN`；
- 多行顺序执行、逐条保存和检查点恢复通过；
- 执行报告与 Excel 结果一致；
- 已冻结品牌和渠道回归通过；
- 用户完成华为真站测试并确认通过。
