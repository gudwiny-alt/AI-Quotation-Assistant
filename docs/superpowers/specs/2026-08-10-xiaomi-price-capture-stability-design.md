# 小米官网取价稳定与 80% 同屏截图设计

日期：2026-08-10  
适用基线：小米官网 `.54`；荣耀、京东、天猫、其他品牌和 Excel 冻结

## 1. 问题与证据

`.54` 已能从小米搜索结果进入商品详情页，但本次 `Xiaomi 17` 与 `Xiaomi 17T` 均在截图前失败。任务检查点记录的共同错误为：

`CAPTURE_UNSTABLE: Xiaomi selected offer did not stabilize within five seconds`

当前价格逻辑把“等待首次有效价格出现”和“确认价格连续稳定”共同限制在五秒内，并要求有效价格连续稳定约三秒。慢速加载、配置切换后的价格异步刷新会挤占稳定确认时间，导致价格尚未形成检查点就结束。截图方面，100% 页面可能无法让产品标题、价格、容量和颜色同屏；滚动到配置区域后标题离开画面，正式截图校验因证据不完整而拒绝保存。

## 2. 范围

只修改小米官网独立适配器及其小米专项测试：

- 不修改荣耀官网；
- 不修改京东和天猫；
- 不修改 OPPO、vivo、华为、苹果；
- 不修改 Excel 写入、报告、截图运行时和公共任务调度行为。

## 3. 取价流程

取价拆分为两个有界阶段：

1. **等待首次有效价格**：最长约十秒。每次读取仍须满足现有小米价格规则：目标详情页、目标容量与颜色已选中、价格属于购买摘要中的当前商品、为有效红色销售价，并排除划线价、优惠券、补贴、分期和其他污染金额。
2. **确认价格稳定**：首次读到有效价格后开始稳定计时，要求同一商品身份、容量、颜色和价格连续稳定约三秒。价格发生变化时只重置稳定计时，不重新搜索商品；页面身份、配置或价格结构出现歧义时继续封闭失败。

十秒不是固定等待。页面越早出现有效价格，越早进入稳定确认；稳定条件一旦满足，立即保存价格、详情 URL 和检查点。截图失败不得清空已保存价格。

## 4. 80% 同屏截图流程

价格检查点保存后进入正式截图阶段：

1. 将小米详情页设置为 80% 缩放；已经是 80% 时不重复操作。
2. 等待缩放引起的页面重排稳定，然后重新获取产品标题、目标价格、容量区域和颜色区域，不复用缩放前的元素位置。
3. 若四项已同时位于当前可视区域，立即进行业务状态复核并截图，不滚动。
4. 只有四项未同屏时，才执行一次最小幅度的定向滚动，使证据组合进入可视区域。
5. 滚动后重新读取元素位置，并再次确认标题、价格、容量和颜色同屏；满足条件后立即截图。
6. 截图前后复核商品身份、目标容量、目标颜色和价格均与检查点一致；不一致则拒绝截图，但保留价格检查点。

不采用固定滚动、反复缩放、来回试探滚动或拼接截图。

## 5. 异常处理

- 十秒内没有出现唯一有效价格：价格阶段技术失败，不写入臆测价格。
- 有效价格持续变化而不能连续稳定：价格阶段技术失败。
- 价格已稳定并保存，但 80% 下四项仍无法同屏：只标记截图失败，保留价格和详情 URL。
- 页面出现登录、验证、域名漂移、机型或配置漂移：沿用现有暂停或封闭失败机制。

## 6. 测试与验收

按测试驱动方式至少覆盖：

1. 价格延迟出现但在十秒上限内，随后稳定三秒并成功保存；
2. 价格立即出现时不等待满十秒；
3. 价格变化后重置稳定计时，最终稳定后保存；
4. 价格已保存但截图失败时，价格检查点和最终 AK 不被清空；
5. 截图阶段只对小米执行幂等 80% 缩放；
6. 80% 后四项已同屏时不滚动并立即截图；
7. 80% 后不同屏时只进行一次最小定向滚动；
8. 缩放或滚动后状态发生变化时拒绝截图；
9. 荣耀、京东、天猫、其他品牌、Excel 和打包冻结回归全部通过。
