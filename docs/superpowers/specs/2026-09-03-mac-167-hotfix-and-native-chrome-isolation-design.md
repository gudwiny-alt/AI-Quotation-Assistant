# Mac `.167` 热修与全渠道独立 Native Chrome 设计

## 目标

以 `v0.167-stable` 为不可修改的稳定基线，在独立 Mac 分支中完成四项已确认热修，并把品牌官网、天猫、京东改为按渠道顺序执行的独立普通 Chrome 会话。最终仍按“品牌官网 → 天猫 → 京东”串行执行，任一渠道的窗口、登录状态或技术失败不得污染后续渠道。

## 稳定边界

- `v0.167-stable` 标签及其提交保持不变。
- Windows 分支不参与本轮修改；Mac 验证完成后再决定是否移植。
- 不重写任何已经通过的品牌搜索、详情页导航、颜色选择、容量选择、取价或截图业务规则。
- 京东本轮只修复浏览器窗口与正式截图几何，不修改已稳定的京东站点适配器。
- 华为本轮只修复官网主商品价格候选排序，不改变截图优先、截图成功后永久保留的既有规则。
- 小米本轮只修复官网“未找到机型”截图前可见搜索框内容，不重新提交已经确认的搜索结果。

## 已确认故障

### 京东统一失败

最近一次运行中，六条京东任务均完成了搜索或进入详情页，部分任务也已取得价格；但三次截图尝试统一以 `CAPTURE_GEOMETRY` 结束。京东专用 Chrome 的实际窗口被系统压到工作区边缘，而视觉审核启动参数要求的窗口高度超过当前可用工作区。故障属于浏览器窗口/正式截图几何层，不属于京东搜索或详情页业务逻辑。

### 华为官网误取 `199`

华为证据截图正确显示畅享 90 Pro Max、所选颜色、256GB 和 `¥2199`。截图后取价逻辑遍历了页面中多个 `[data-prdid]` 商品区域，并在主商品 `2199` 之前接受了推荐商品或配件的 `199`。现有页面脚本已计算 `primaryDetailRoot`，但价格筛选没有使用该标志。

### 小米官网搜索框内容错误

小米页面 URL 的 `keyword` 已是 `REDMI R70 5G`，无结果区域也正确；但可见搜索框仍显示站点推荐词 `REDMI K90 至尊版`。现有验证只要求“存在可见输入框＋URL 参数正确”，没有验证输入框的实际值。

### Excel 图片锚定方式

当前工作簿已经内嵌图片二进制，图片使用 `oneCellAnchor` 定位到对应行列，但显示宽高固定。调整行高或列宽时，图片不会可靠地随单元格同步缩放。

## 方案

### 1. 京东安全窗口几何

在 `MacFormalCaptureRuntime` 提供的启动/预检边界中，根据 macOS 当前工作区计算带安全内边距的可见窗口矩形。窗口不得贴住工作区四边、不得超过可用高度、不得处于最大化状态。京东 `NativeChromeCdpSession` 启动后和每次正式截图前都执行同一套幂等预检。

底层几何失败保留具体诊断字段，包括期望矩形、实际窗口矩形、工作区矩形和失败阶段；用户界面仍显示简洁错误。不得把截图失败误报为搜索失败。

### 2. 华为主商品价格优先

华为后置取价分两层：

1. 只在包含当前详情标题 `#prd-detail-name[data-testid="prd-detail-name"]` 的主 `[data-prdid]` 根节点内筛选当前价格；
2. 如果主根节点内没有合法现价，返回“截图成功、取价失败”，不得退化为推荐商品、配件、补贴额度或分期金额。

价格仍从网页 DOM 读取，不从截图 OCR 识别。截图先保存，后置取价失败不得删除或覆盖截图。

### 3. 小米无结果截图搜索框

小米无结果状态已由 URL 参数和结果区域确认后，在 `prepare_capture_view` 阶段重新定位当前可见搜索框，调用 `fill(task.model_name)`，再校验 `input_value()` 与任务型号完全一致。该操作不按回车、不点击搜索按钮、不改变 URL、不重新计算业务结果。填充完成后重新读取搜索框与无结果区域矩形，再等待固定的短暂稳定时间并截图。

### 4. Excel 图片随单元格移动和缩放

保留图片二进制内嵌，改用 `twoCellAnchor`：起点是目标单元格左上角，终点是同一单元格右下角。图片对象随所在行列移动，并在用户调整行高或列宽时同步缩放。

为避免横纵比严重失真，程序继续把截图单元格设置为统一列宽和行高；图片初始显示区域使用单元格内边距。工作簿重新打开后必须仍保留双边界锚点和图片媒体文件。该方式优先保证 Excel 与 WPS 的本地文件兼容，不使用依赖外部 URL 的 `IMAGE()` 公式。

### 5. 全渠道独立 Native Chrome

把当前两个浏览器阶段拆成三个串行阶段：

1. 品牌官网：`NativeChromeCdpSession`＋`browser-profile-official`；
2. 天猫：`NativeChromeCdpSession`＋现有 `browser-profile`，保留既有登录状态；
3. 京东：`NativeChromeCdpSession`＋`browser-profile-jd`。

Native Chrome 的含义是程序先启动普通安装版 Chrome，再通过本机 CDP 接口附加 Playwright；站点适配器仍使用现有 Playwright 页面 API。每个阶段结束后关闭自己的 Chrome 进程并释放用户目录锁，再启动下一阶段。

渠道阶段必须相互隔离：一个阶段启动失败或任务技术失败，只记录该阶段结果并继续下一阶段。人工登录/验证仍通过现有“继续当前任务”机制恢复，不能自动复制 Cookie 或修改用户的日常 Chrome 资料。

迁移顺序固定为：先验证京东安全几何，再切换天猫，最后切换品牌官网。每一步都必须通过现有渠道回归矩阵后才能进入下一步。

## 测试策略

### 京东

- 窗口请求尺寸超过工作区时，预检会缩小并内缩到安全矩形。
- 独立 Chrome 恢复出贴边窗口时，正式截图前会归一化。
- 六品牌京东站点适配器合同测试保持不变并全部通过。

### 华为

- 页面先出现推荐商品 `¥199`、后出现主商品 `¥2199` 时，结果必须为 `2199`。
- 主商品价格缺失但推荐区有价格时，必须保留截图并返回取价失败。
- 截图路径和已选择颜色/容量不因后置取价失败而回滚。

### 小米

- URL 关键词正确但搜索框显示推荐词时，截图准备后输入框必须显示任务型号。
- 不触发新的导航或搜索提交。
- 重新计算的两个证据矩形仍对应搜索框和无结果区域。

### Excel

- 输出文件包含图片媒体文件。
- 每张图片使用目标列和目标行的 `twoCellAnchor`。
- 保存并重新打开后，起止锚点仍包围同一个单元格。
- 没有截图的渠道不生成占位图片。

### 全渠道会话

- 官网、天猫、京东按既定顺序各创建一次 `NativeChromeCdpSession`。
- 三个阶段使用三个稳定且互不相同的用户目录。
- 前一阶段故障不阻止后一阶段执行。
- 天猫继续使用原用户目录，现有登录状态无需迁移。

## 验收标准

- 最近一次七条基础表可完整执行，京东不再统一报 `CAPTURE_GEOMETRY`。
- 华为畅享 90 Pro Max 官网价写入 `2199`，不得写入 `199`。
- REDMI R70 5G 无结果截图中，可见搜索框明确显示 `REDMI R70 5G`。
- Excel 图片位于对应截图单元格，调整行高或列宽时随单元格同步移动和缩放。
- 官网、天猫、京东分别在独立普通 Chrome 会话中串行完成。
- 已通过的其他品牌和渠道回归测试全部通过。

## 不在本轮范围

- 修改报价表字段映射或渠道列定义。
- 修改商品匹配、颜色匹配、容量匹配规则。
- 修改网站执行顺序。
- 自动迁移日常 Chrome 的 Cookie、密码或扩展。
- Windows 平台适配或打包。
