# 荣耀官网基线验收设计

## 目标

先只验收基础表中全部荣耀（`HONOR`）行的荣耀官网闭环：三表关联、官网查价、官网截图、报价表 `AK`/`AN` 写入和执行报告。京东、天猫本轮不得启动、不得出现在任务统计中、不得影响荣耀官网行的结果。

## 方案选择

采用“任务边界筛选”方案，而非修改荣耀官网适配器或用新搜索策略重建官网流程。

在完成现有三表关联、筛出全部 `HONOR` 行并按现有方式创建网站任务后，只把 `official` 渠道任务交给持久化任务仓库、浏览器运行器、增量发布器和最终 Excel/报告写入器。由于下游从未收到京东、天猫任务，浏览器不会打开这两个站点；报告也不会把它们算作失败、等待登录或人工补充。

## 用户界面与运行模式

当前“仅 HONOR”模式扩展为两种明确的运行范围：

1. `荣耀官网验收（仅官网）`：传入 `selected_brand="HONOR"` 和仅 `WebsiteChannel.OFFICIAL` 的渠道集合。本轮默认选中它。
2. `荣耀全站闭环（官网、京东、天猫）`：保留现有三渠道行为，暂不作为本轮验收范围。

状态区必须显示“荣耀官网验收模式（仅官网）”，以免产品经理误以为京东或天猫会运行。

## 数据与结果规则

- 输出报价表只含基础表中全部荣耀行，顺序保持不变；自动关联字段和公式按既有流程填入。
- 官网成功时，`AK` 写入官网价格，`AN` 嵌入官网截图；`AI`、`AJ`、`AL`、`AM` 保持空白，因为本轮未运行相应渠道。
- 每条荣耀行只依据官网任务状态参与本轮报告：官网成功为完成；官网技术失败为失败；官网等待登录为待人工补充。不得因未计划的京东/天猫任务改变行状态。
- 运行器只接收官网任务，因而事件流、浏览器导航、任务数据库和执行报告均不应出现 `jd` 或 `tmall`。

## 回归与发布护栏

2. 新增端到端写入测试：两条荣耀官网成功结果写入两行的 `AK` 和两张 `AN` 截图；京东、天猫列为空；报告为两条完成。
3. 新增 UI 请求测试：默认“荣耀官网验收（仅官网）”会向完整管线传递 `HONOR` 与官网渠道集合。
4. 新增冻结护栏测试：`official.py` 和 `official_overrides/honor.py` 的内容指纹必须与本次建立的基线一致。任何未来改动都会使测试失败，不能悄悄打包。
5. 打包前运行官网回归组、完整相关回归组、静态类型检查和 macOS 签名校验。只有这些检查均通过才生成独立的“荣耀官网验收版”安装包；不覆盖历史包。

## 非目标

- 不修复京东、天猫，不访问其页面，不要求其登录。
- 不修改荣耀官网搜索、详情页、规格选择、价格解析、截图或 Excel 写入模块。
- 不清理既有输出文件、浏览器资料或历史安装包。
