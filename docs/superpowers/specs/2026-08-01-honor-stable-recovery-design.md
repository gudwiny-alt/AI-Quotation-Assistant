# 荣耀官网稳定恢复设计

## 目标

恢复并验证基础表中全部 `HONOR` 行的荣耀官网闭环：关联字段、官网价格、官网截图、逐行写入报价表和执行报告。本阶段不启动京东、天猫，不修改其代码，也不把其状态计入荣耀官网验收结果。

## 已证实的故障边界

2026-08-01 的两条荣耀官网任务都在“官网首页提交搜索”后 1--3 秒内以 `LAYOUT_CHANGED` 失败；没有形成网站观察结果、没有进入截图阶段，也没有可供 Excel 写入的价格或图片。当前代码在点击搜索后只等待 `domcontentloaded`；首页本身已满足该状态，因此没有等待异步结果卡片渲染。

“处理中”报价表和报告是增量检查点，并非新增报价行：最终文件仍只有两条产品行。成功完成最终报价表和执行报告后，用户只需要保留最终两份文件。

## 方案与边界

### 1. 荣耀入口兼容层（唯一允许触及官网适配器的改动）

只修改 `OfficialStoreAdapter._observe_honor_live()` 的“填入关键词、提交搜索、确认结果卡片”入口片段：

1. 填入型号并点击搜索；
2. 以短周期轮询、总时限的方式等待荣耀结果区域和产品卡片，不以固定长睡眠或 `domcontentloaded` 代替；
3. 若点击后没有结果，向同一个搜索框发送一次 `Enter`；再次使用同一等待规则；
4. 仍无结果时，保留当前页面并以清晰的 `LAYOUT_CHANGED` 原因结束该条任务，不再连续三次重新导航首页。

禁止修改荣耀详情页跳转、型号匹配、规格选择、价格解析、截图语义校验、Excel 写入逻辑。原有源码整体哈希护栏将改为“入口兼容层有专门行为测试；详情/规格/价格/截图路径仍受内容指纹保护”，防止后续借本次例外改动已验证链路。

### 2. 页面等待、窗口与滚动

页面“可处理”的定义是语义就绪：目标型号的唯一结果卡片（或详情页所需价格、规格）已存在，而不是浏览器刚结束加载。每次任务只使用同一个自动化页面；失败不会新开标签页。

macOS 测试版维持“程序启动窗口、产品经理手动摆好、随后不由程序调整尺寸”的规则。运行前检查增加窗口可用高度/前台状态的提示性检查；不满足时阻止启动并告诉用户调整后重新检查。程序不自动最大化、缩放或移动窗口。

只有页面已经进入正确详情页、价格和已选配置语义校验完成后，截图阶段才执行受控滚动：先将目标配置和价格区滚入视窗、等待短暂稳定、复核元素仍可见后截图。截图阶段不会靠滚动寻找产品，也不会跨页面滚动。

### 3. 异常与继续机制

错误按原因分流：

- 登录/验证码：停留在当前页面，提示人工完成，点击“继续当前任务”后只恢复本条站点任务；
- 可恢复的页面渲染/窗口就绪问题：保留当前页，提示调整窗口或等待后继续；
- 搜索结果始终未出现或结构变化：停止本条任务并在报告写明阶段与原因，不反复刷新页面；
- 无此机型/无匹配规格：作为业务结果处理，不要求人工登录；
- 关联数据缺失：不打开浏览器，直接进入报告。

不为每条失败都人工确认；同一站点登录状态或窗口问题只暂停当前任务，确认后按原子任务恢复。

### 4. 文件交付

运行中持续以 `-处理中.xlsx` 对保存中断提供恢复保护。仅当最终报价表与最终执行报告都已成功生成后，安全删除本次运行的两份同名“处理中”文件；失败、中断或最终写入失败时保留它们。

## 验收与回归

1. 合同测试覆盖“点击即出结果”和“仅 Enter 后出结果”，并证明进入既有详情、规格、价格语义路径。
2. 多条荣耀官网任务的集成测试覆盖逐行即时检查点写入；任一条失败不得抹除先前成功行。
3. 窗口预检、受控滚动/稳定截图和登录暂停均有单元或合同测试；不需要真实网页登录来断言这些逻辑。
4. 成功的管线只留下最终报价表与最终报告；异常管线保留一对处理中检查点。
5. 打包前运行荣耀合同、官网范围、增量发布、窗口运行时和全量测试；构建新安装包，不覆盖历史安装包。

## 非目标

- 本阶段不修复京东、天猫，不访问它们，也不要求它们登录。
- 不读取、导出或重置浏览器登录资料。
- 不自动修改 macOS Chrome 的窗口位置、尺寸、缩放或全屏状态。
