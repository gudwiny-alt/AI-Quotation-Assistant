# OPPO 官网详情页提前 80% 缩放设计

**日期：** 2026-08-12  
**状态：** 用户已审核；实现时补充异常清理约束
**范围：** 仅 OPPO（欧珀）品牌官网；不修改荣耀、小米、京东、天猫、Excel 或其他品牌官网。

## 1. 背景与根因

`.66` 真机测试已经验证：OPPO A5m 与 A6t 都能从搜索结果页进入正确的产品详情页，缺货与是否显示 5G 不再阻碍导航。

同一轮测试中：

- A6t 完成取价与截图；
- A5m 连续三次在详情页识别阶段以 `LAYOUT_CHANGED` 失败，未保存价格检查点，说明失败发生在正式截图之前；
- A5m 页面在滚动后无法让产品标题、价格、容量、颜色同时位于当前视口。

当前实现只在 `prepare_capture_view` 阶段发现四项证据不能同屏后才切换到 80%。这个时机太晚：在进入截图准备前，程序已经需要识别标题、容量、颜色和价格，A5m 可能在这个阶段因视口信息不足而失败。

## 2. 目标与非目标

### 2.1 目标

1. 进入合法 OPPO 产品详情页后，立即把页面设置为 80%。
2. 在 80% 状态下完成标题识别、容量与颜色选择、价格读取和截图。
3. 四项证据——产品标题、当前价格、目标容量、目标颜色——已经同屏时直接截图。
4. 四项尚未同屏时，最多执行一次定向滚动，再复核后截图或封闭失败。
5. 保持 A6t 已成功流程，并解决 A5m 因详情页视口不足造成的失败。

### 2.2 非目标

- 不改变 OPPO 搜索结果页的商品卡匹配和详情链接规则。
- 不改变缺货、5G、型号精确匹配、容量/颜色匹配或价格取值规则。
- 不放宽“四项证据必须同屏”的正式截图标准。
- 不修改合法“无机型/无容量/无颜色”的证据规则。
- 不修改其他网站和最终 Excel 写入逻辑。

## 3. 方案选择

采用“详情页先缩放、再处理”的方案：

1. 搜索结果页继续使用当前视图，不提前缩放。
2. 取得精确商品卡的合法详情 URL 后执行导航。
3. 详情页完成 `domcontentloaded` 且 URL 通过校验后，幂等设置 80% 缩放。
4. 随后才等待标题、选择容量和颜色、等待报价稳定。
5. 业务识别完成后先恢复进入详情页前的缩放，避免检查点、权限或窗口异常把 80% 泄漏给后续任务。
6. 正式截图准备在读取四项证据前再次幂等确保 80%，截图完成或失败后恢复原缩放。

不采用“只在截图前缩放”，因为 A5m 已在截图前失败。也不采用反复滚动或依赖人工窗口高度，因为这些方案会增加页面漂移和不稳定性。

## 4. 详细流程

### 4.1 首次详情页处理

```text
搜索结果稳定
  → 精确机型卡 + 合法 OPPO 商品链接
  → 导航到详情页
  → 校验详情 URL
  → 幂等设置页面为 80%
  → 等待精确标题
  → 等待并选择目标容量
  → 等待并选择目标颜色
  → 等待目标报价稳定
  → 保存价格与详情 URL 检查点
```

### 4.2 恢复处理

当程序从已经验证的 OPPO 详情页检查点恢复时：

1. 导航到检查点 URL；
2. 校验仍为合法 OPPO 详情页；
3. 幂等设置 80%；
4. 再复核标题、容量、颜色和价格。

这样首次处理与恢复处理遵循同一视口规则，不会因重启后回到 100% 而产生不同结果。

### 4.3 截图处理

正式截图准备在读取任何证据前幂等确保页面为 80%。这样既保证截图判定使用 80% 布局，也使业务识别与正式截图之间的检查点、权限和窗口准备阶段保持原缩放。

1. 获取产品标题、当前价格、目标容量、目标颜色四个定位元素；
2. 若四项当前已在同一视口，立即通过；
3. 若没有同屏，计算四项联合区域并执行一次定向滚动；
4. 再次获取四项并复核；
5. 复核通过则截图；仍不通过则以结构识别失败结束，不生成误导截图。

截图完成或任务失败时，沿用现有清理机制恢复页面缩放，避免影响后续搜索页或其他网站任务。

## 5. 幂等与稳定性规则

- 已经是 80% 时，不重复写入缩放值，不产生视觉跳动。
- 每次详情页业务识别前执行一次“确保 80%”，识别完成即恢复。
- 每次正式截图准备前再执行一次“确保 80%”，若当时已经是 80% 则不重复写入。
- 价格稳定等待期间不再缩放或滚动。
- 截图准备阶段最多执行一次定向滚动，禁止上下反复寻找位置。
- 每次滚动后必须重新获取元素定位，避免使用滚动前的旧矩形。

## 6. 错误处理

- 缩放动作执行失败：技术失败，不继续以不确定视口取价或截图。
- 业务识别成功或失败：都必须恢复进入详情页前的缩放，保证后续检查点、权限和窗口失败不会遗留 80%。
- 80% 下仍找不到精确标题、容量、颜色或价格：沿用当前结构识别/配置不可用规则。
- 四项无法同屏：一次定向滚动后仍失败，则不截图并记录技术失败。
- 已保存价格检查点但截图失败：保持既有增量保存规则，不清空已验证价格和详情 URL。

## 7. 测试与回归保护

新增或强化以下契约：

1. 详情页必须在标题/容量/颜色/价格读取前进入 80%。
2. 首次观察与检查点恢复均遵守提前 80%。
3. 已经是 80% 时不得重复缩放。
4. 四项在 80% 下同屏时零滚动并可截图。
5. 四项初始不同屏时最多滚动一次；滚动后同屏可截图。
6. 一次滚动后仍不同屏时封闭失败。
7. A5m 与 A6t 两个机型均完成对应契约。
8. OPPO 搜索商品卡、缺货卡、精确型号、价格和合法“无”契约保持通过。
9. 荣耀、小米、京东、天猫和 Excel 代表性回归保持通过。

## 8. 验收标准

- 真机运行中，A5m 和 A6t 进入详情页后可观察到一次 80% 缩放；
- A5m 不再因标题、价格、容量、颜色无法同屏而在截图前失败；
- A5m 与 A6t 均能写入官网价格和正式截图；
- 已通过的 OPPO 搜索导航、荣耀、小米、京东和天猫功能无回归；
- 新 Mac 测试包使用独立版本目录，不覆盖 `.66`。
