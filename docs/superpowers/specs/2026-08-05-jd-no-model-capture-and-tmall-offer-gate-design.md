# 京东无报价截图与天猫报价校验最小修复设计

## 背景与证据

2026-08-05 的两条荣耀实机运行中：

- 京东“荣耀畅玩80”已经正确判定为“无该机型”，但正式截图连续三次报
  `CAPTURE_GEOMETRY / 正式截图搜索框定位失败`。
- 天猫“荣耀Power2”进入详情页后，连续三次报
  `LAYOUT_CHANGED / Tmall delivery region structural element is missing or ambiguous`。
- 已成功且不得回退的基线包括：荣耀官网两条任务、京东 Power2 价格 2699 与截图、
  天猫畅玩80“无该机型”与截图。

## 目标

只消除上述两个错误门槛，不改变商品匹配、价格口径、Excel 写入和已成功渠道的行为。

## 方案选择

### 京东

采用“稳定等待可见关键词”的最小方案：保留“正式截图必须显示搜索关键词”的规则，
但不再以截图准备阶段某一次瞬时 DOM 读取作为成败依据。观察阶段已经确认无报价后，
截图阶段在有限等待期内扫描所有可见店内搜索框；只要任一个稳定显示目标型号，就定位
结果区并截图。始终未显示目标词时仍失败，不使用 URL 代替画面证据，也不伪造输入值。

不采用以下方案：

- 完全取消截图前关键词校验：可能生成无法证明搜索对象的截图。
- 自动重新填词并重新搜索：会改变已验证结果页，增加刷新和风控风险。

### 天猫

采用“库存与收货地区降级为非报价证据”的最小方案：价格成功的硬条件仅保留受控商品
详情页、官方店铺、匹配型号、目标内存容量、目标颜色和有效价格。库存文字与收货地区
不再参与价格稳定性或截图准入；它们不是本报价任务需要输出的字段。

天猫仍只在详情校验成功、进入正式截图准备阶段后切换到 80% 缩放，并要求标题、价格、
内存容量和颜色同屏可见。

不采用以下方案：

- 仅增加更多收货地区选择器：仍把无关字段当成硬门槛，页面再次变化还会失败。
- 全面放宽详情页校验：会削弱商品、配置和价格的必要证明。

## 数据流与错误处理

1. 查价阶段生成并保存业务观察检查点。
2. 京东无报价截图只重试可见关键词与结果区的稳定展示，不重新执行搜索。
3. 天猫价格观察不再读取或比较收货地区、库存状态；配置和价格稳定后生成检查点。
4. 正式截图前重新验证与本任务有关的字段；验证不通过仍按现有技术失败机制处理。
5. 单站失败不覆盖同一行其他站点已成功保存的价格或截图。

## 回归保护

新增测试必须先在旧代码上失败，并覆盖：

- 京东无报价页：搜索框先短暂为空、随后出现目标词时可截图；始终没有目标词仍失败。
- 天猫详情页：没有唯一收货地区元素，但型号、内存、颜色和价格完整时可成功。
- 天猫目标内存、颜色或价格缺失时仍失败。
- 现有荣耀官网、京东 Power2、天猫畅玩80基线全部通过。

## 验收标准

- 京东畅玩80继续输出价格“无”，并生成同时包含目标搜索词与非匹配商品结果的截图。
- 天猫 Power2 写入价格并生成标题、价格、12GB+256GB、黑色同屏截图。
- 天猫 Power2 在正式截图前可见 80% 缩放；若在更早的必要字段校验失败，不生成截图。
- 既有成功的官网、京东 Power2 和天猫畅玩80结果不回退。
