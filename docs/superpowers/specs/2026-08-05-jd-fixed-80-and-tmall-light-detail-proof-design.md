# 京东固定 80% 与天猫轻量详情页证明设计

## 目标

在不修改荣耀官网、Excel 写入和既有价格政策的前提下，修复本轮三个问题：京东正式截图阶段反复缩放、京东畅玩80只识别单一搜索框、天猫 Power2 因多个匹配标题被阻断。

## 已确认事实

- 京东 Power2 已完成机型、配置和划线价 `2699` 的验证，失败发生在最终原生截图阶段。
- 京东畅玩80已经正确形成“无该机型”业务结果；结果页存在两个可见搜索框，其中店内搜索框包含“荣耀畅玩80”。
- 天猫 Power2 已从匹配商品卡进入受控详情 URL；当前标题快照要求所有匹配标题归一化后只剩一个文本，页面同时存在短标题和营销长标题时会被判为歧义。

## 设计

### 1. 京东任务固定为 80%

- 京东每次进入或恢复页面后立即应用并证明 `0.8` 页面比例。
- 搜索页导航和详情页导航完成后重新确保 `0.8`，因为新文档不会继承上一文档的 CSS 缩放。
- 同一页面上的报价校验、最终取景、正式截图及截图重试不再恢复后重新应用比例。
- `prepare_capture_view` 只证明当前比例仍为 `0.8` 并定位证据，不执行“恢复—等待—重缩放”循环。
- 京东截图结束后的站点恢复钩子不把当前页面切回 100%；后续新站点导航会创建新文档并按该站点自己的规则处理。

### 2. 京东无报价页接受任意匹配的可见搜索框

- 搜索框候选包含店内搜索框和页面顶部全站搜索框。
- 遍历所有可见候选，只保留输入值归一化后等于当前机型的搜索框。
- 至少一个候选匹配即通过；多个匹配时按定位器优先级选择第一个，不因页面同时存在两个搜索框而失败。
- 没有匹配搜索框时仍拒绝截图；不得仅凭 URL 或商品列表推断搜索词。
- 正式截图继续要求所选搜索框与至少一个不匹配商品名称同屏。

### 3. 天猫详情页采用轻量一致性证明

- 搜索结果商品卡仍负责主要机型确认，并继续排除 Pro、Plus 等不同型号。
- 详情页仍必须满足：受控天猫商品 URL、官方旗舰店卖家、至少一个可见标题能匹配基础机型、目标容量与颜色、有效价格状态。
- 多个可见标题只要都能证明同一基础机型即可，不再要求其完整营销文本唯一。
- 稳定快照保存标准化基础机型身份，而不是任一完整标题文案；短标题和营销长标题之间的差异不再使价格轮询失败。
- 完全没有匹配标题、跳到广告页、登录页或非官方卖家时仍然拒绝。

## 保存与错误边界

- 京东价格已保存而截图失败时继续保留价格。
- 京东“无该机型”已保存而截图失败时继续保留“无”。
- 天猫只有通过详情页轻量一致性证明后才读取并保存价格。
- 本轮不改官网、输出表结构、渠道顺序和价格优先级。

## 验收标准

1. 京东同一页面发生最多三次正式截图尝试时，页面保持 `0.8`，不存在恢复为 `1.0` 后再缩放的循环。
2. 京东 Power2 在标题、划线价、幻夜黑、12GB+256GB 同屏后可直接生成截图，价格仍为 `2699`。
3. 京东畅玩80存在两个搜索框、其中任意一个包含目标词时，可生成包含目标搜索框和不匹配商品名称的截图。
4. 天猫 Power2 同时存在短标题和营销长标题时仍可完成价格稳定验证及截图；无匹配标题仍拒绝。
5. 京东、天猫契约测试、macOS 截图运行时测试、荣耀官网基线和全量测试全部通过。
