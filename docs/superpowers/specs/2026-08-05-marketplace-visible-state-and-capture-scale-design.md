# 京东、天猫可见状态判定与截图缩放修复设计

## 背景与本次证据

2026-08-05 的 `.42` 测试运行中，荣耀官网两行均能正常写入价格和截图，Excel 输出链路有效；失败集中在三个独立环节：

- 京东 Power2 已进入正确详情页，但配置校验报告 `JD modern exact configuration did not reach an exclusive stable state`，未生成价格和截图。
- 天猫 Power2 已进入正确详情页，但配置校验报告 `Tmall selected capacity SKU binding is missing or invalid`，未生成价格和截图。
- 京东畅玩80已正确判定“无该机型”，但 macOS 正式截图上下文组合失败，因此“无”已写入而截图为空。

用户现场观察还表明，京东畅玩80在失败前肉眼看起来没有保持 80% 缩放。现有实现只验证写入了 CSS `zoom` 属性；若后续页面校验失败，清理逻辑会立即恢复原比例，所以“调用过缩放”并不能证明正式截图阶段实际处于 80%。

## 设计原则

1. 荣耀官网适配器、官网取价、官网截图和 Excel 写入逻辑完全不修改。
2. 京东、天猫以用户可见且可核验的产品标题、容量、颜色、价格和搜索结果为业务证据，不再把站点不稳定的隐藏属性作为成功的必要条件。
3. 配置验证仍然必须精确：机型匹配、目标容量唯一选中、目标颜色唯一选中；套餐、服务、保障等其他已选控件不得被误判为颜色。
4. 80% 缩放只用于最终判断和正式截图阶段，并必须实际生效且保持到截图成功发布之后。
5. 三类失败独立处理、独立测试，任何修复不得使一个渠道的失败覆盖另一渠道或官网已保存的结果。

## 方案选择

### 采用：可见状态契约 + 有界截图准备重试

- 京东和天猫通过可见选中状态确认目标容量、颜色。
- 价格在配置稳定后连续读取两次；两次页面配置和价格一致才接受。
- 截图准备阶段验证真实缩放、定位和证据矩形；准备失败只重试一次该阶段，不重新搜索、不重新进入详情页。

该方案直接对应业务验收内容，且不依赖网页内部未承诺的属性。

### 不采用：继续补隐藏 SKU 属性兼容

这种方案改动较小，但真实网页可能再次更换 `data-sku`、`data-current-sku` 或组件结构，仍会出现“页面肉眼正确、程序判定失败”。

### 暂不采用：Mac 失败时退化为浏览器视口截图

该方案截图成功率较高，但会丢失整屏和菜单栏证据，与现有 Mac 验收格式不一致。只在原生整屏方案经后续实测仍无法稳定时再单独讨论。

## 京东 Power2

### 配置判定

程序从所有 SKU 控件中分别寻找：

- 唯一一个与基础表内存、容量匹配且处于可见选中状态的容量控件；
- 唯一一个与基础表颜色匹配且处于可见选中状态的颜色控件。

“官方标配”、套餐、服务和保障等控件即使处于选中状态也忽略，不参与颜色数量统计。是否有货不影响配置选择和截图；只要颜色、容量控件可以选择或已经选中，就继续取价。

### 取价

完成容量和颜色选择后，连续取得两份相同的可见状态快照。快照包含标题、选中容量、选中颜色和价格候选。按照现有报价规则优先取得目标配置的划线价；Power2 当前页面应取得 `2999`。补贴后价、券后价不得替代划线价。

## 天猫 Power2

天猫不再要求容量控件具有数字型 `data-sku`，也不再要求颜色控件与隐藏的 current-SKU 标记编号相等。替代验证为：

1. 产品详情页标题精确匹配 Power2；
2. 目标容量唯一可见并处于选中状态；
3. 目标颜色唯一可见并处于选中状态；
4. 连续两次读取的标题、容量、颜色和价格一致；
5. 页面在两次读取之间没有跳回搜索页、登录页或风控页。

满足以上条件后按天猫现有报价规则取价并截图。

## 京东畅玩80无报价截图

无报价业务判定保持不变：搜索词为畅玩80，结果区不存在精确匹配的畅玩80商品卡，即写入“无”。正式截图必须同时包含：

- 能证明本次搜索关键词的店内搜索框；
- 显示实际搜索结果商品名称的结果区域。

截图准备流程为：

1. 将页面切换至 80%；
2. 读取并确认页面实际比例为 `0.8`；
3. 连续两次读取 `document.documentElement.style.zoom` 和计算后的 `zoom`，两者均为 `0.8`，并确认搜索框及结果卡的屏幕矩形已经按缩放后的布局重新计算；
4. 定位搜索框和结果商品名称，使两者同时可见；
5. 等待一轮稳定采样后重新读取两块证据矩形；
6. 绑定当前 macOS 浏览器窗口并生成整屏截图；
7. 截图文件完成校验和原子发布后才恢复原页面比例。

如果步骤 2—6 出现瞬时窗口或布局变化，只从步骤 1 重试一次；不得重新搜索，也不得覆盖已确认的“无”结果。第二次仍失败时，报告必须保留失败的具体阶段，而不是只显示笼统的“截图上下文组合失败”。

## 错误和保存边界

- 每个渠道观察完成后立即保存该渠道结果，不等待三个渠道全部结束。
- 取价成功但截图失败时保留价格，并在报告中标记“截图待补”。
- “无该机型”判定成功但截图失败时保留“无”，并标记“截图待补”。
- 京东或天猫失败不得清空官网价格、官网截图或其他渠道已经保存的结果。

## 测试与验收

实现必须先增加失败测试，再修改生产代码。至少覆盖：

1. 京东同时选中容量、颜色和官方标配时，仍能确认目标配置并取得划线价 2999。
2. 京东存在多个真正匹配颜色或容量时拒绝继续，防止放宽成模糊匹配。
3. 天猫容量、颜色可见且稳定，但没有 `data-sku` 时仍能成功取价。
4. 天猫可见配置在两次采样间变化时拒绝取价。
5. 京东畅玩80无报价页只有在内联值和计算值连续两次均确认为 0.8，且搜索框和结果商品名称同时可见时才允许截图。
6. 截图准备第一次发生瞬时布局变化时只重试准备阶段一次；成功后不重新搜索。
7. 缩放在截图文件发布前不得恢复，截图完成或最终失败后必须恢复。
8. 官网回归测试、Excel 增量保存测试及完整测试套件全部通过。

Mac 实测验收结果应为：Power2 京东和天猫均写入价格及截图；畅玩80京东写入“无”并生成包含搜索词和结果商品名称的截图；两行官网结果保持不变。
