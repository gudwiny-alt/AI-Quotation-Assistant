# 天猫详情页提前 80% 缩放设计

## 背景与根因

2026-08-06 的真实运行中，天猫荣耀 Power2 在登录恢复后连续三次失败，错误均为
`Tmall selected variant price did not reach a verified stable state`。当前流程先在 100%
页面下选择内存和颜色并等待价格稳定；只有观察成功、进入正式截图准备后才应用 80%
缩放。因此价格稳定判断提前失败时，80% 缩放、最终定位和截图都不会发生。

## 目标

确认进入正确且获批的天猫商品详情页后，立即把该详情页固定为 80%，再完成布局等待、
配置选择、价格识别、最终定位和截图。整个详情页任务只设置一次 80%，不在识别和截图
之间来回切换。

## 执行顺序

1. 进入天猫详情页，并校验详情页 URL 与官方旗舰店身份。
2. 立即应用 80% 缩放。
3. 在 80% 状态下等待详情布局稳定。
4. 选择并验证目标内存与颜色。
5. 在同一 80% 状态下等待并确定价格。
6. 正式截图前重新验证 URL、店铺、型号、内存、颜色和价格。
7. 定位包含产品信息与配置区域的截图画面并截图。
8. 任务完成、失败或离开天猫时恢复缩放，且只恢复一次。

## 范围边界

- 只调整天猫 `PRICE_FOUND` 商品详情页的缩放时机与生命周期。
- 天猫无报价搜索结果页保持现有逻辑。
- 产品型号、内存、颜色和价格仍为必须验证的报价条件。
- 库存状态和收货地区仍不参与报价与截图判定。
- 不修改京东、荣耀官网、Excel 写入、价格选择政策及其他品牌流程。
- 不允许通过放宽字段校验掩盖价格不稳定；若 80% 下价格仍无法稳定，应保留明确技术失败。

## 错误与清理

- 详情页缩放后，任意识别、配置选择或价格验证失败都必须恢复缩放。
- 正式截图成功后由现有截图生命周期恢复缩放。
- 登录/验证暂停发生在详情页缩放之前时，不执行无意义的恢复。
- 重试时允许重新进入详情页并再次设为 80%，单次尝试内部不得反复缩放。

## 测试与验收

- 新增失败测试证明旧流程在价格观察之前没有缩放。
- 新流程测试必须证明事件顺序为：详情页校验 → 80% → 配置选择 → 价格读取 → 截图定位。
- 覆盖观察阶段失败时恢复一次、成功后保持 80% 到截图结束、截图后恢复一次。
- 回归天猫 Power2、天猫无报价、荣耀官网、京东、Excel 写入和 macOS 截图运行时。
- 生成独立后继测试包，不覆盖 `.44`。
