# 京东／天猫最终阶段固定 80% 与京东同机型配置回退设计

## 背景与实测证据

以 `.40` 测试包为基线。2026 年 8 月两条荣耀实测中：

- 荣耀官网两条价格及截图均成功，必须保持不变。
- 京东 Power2 已进入正确详情页，但基础表目标容量 `12GB+256GB` 在当前页面不可用，程序提前输出“容量不可用”，没有继续读取同一机型当前可用 `12GB+512GB` 的划线价 `2999`。
- 京东畅玩80已经正确判定“无该机型”，但搜索框与不匹配商品名称在 90% 下仍未通过同屏截图校验。
- 天猫尚未接入最终截图比例调整。

## 目标

1. 京东和天猫只在最终状态复核与正式截图阶段临时切换到 80%；搜索、登录、验证、商品卡点击和详情页进入过程保持原比例。
2. 京东精确机型详情页中，优先使用基础表指定的容量和颜色；若指定配置明确不可用，允许在同一精确机型页面选择一个可用配置继续报价。
3. 京东 Power2 选择可用配置后，按既有最高有效价格规则读取当前配置的已验证划线原价 `2999`，不采用补贴后价或到手价。
4. 京东畅玩80无报价截图同时显示经验证的搜索词和可读的不匹配商品名称。
5. 荣耀官网流程完全不变。

## 方案选择

采用“最终阶段临时 80% + 同机型可用配置回退”方案。

未采用的方案：

- 全查询过程保持 80%：会扩大对登录、风控、搜索输入和页面跳转的影响范围。
- 继续把目标容量不可用写成“无”：与本次 Power2 人工确认的报价规则冲突，也会漏掉页面明确展示的 `2999` 划线价。

## 京东处理规则

### 精确机型与配置

1. 搜索结果仍必须精确匹配当前机型；不得从 Power、Power2 或其他相近型号之间串价。
2. 进入正确详情页后，先尝试基础表指定容量与颜色。
3. 指定容量或颜色可用时继续保持精确选择。
4. 指定配置明确不可用时，从同一详情页选择一个可用容量和一个可用颜色；优先保留页面已经选中的可用项，否则按页面顺序选择首个可用项。
5. 记录并复核实际选中的容量、颜色和 SKU，截图必须展示该实际配置。

### 价格

1. 价格必须绑定当前实际选中的 SKU。
2. 延续京东 `HIGHEST` 价格策略。
3. 当前配置同时显示补贴后价与有效划线原价时，划线原价属于可验证报价候选；Power2 应取得 `2999`。
4. 优惠券、分期金额、以旧换新金额及无法绑定当前 SKU 的数字继续排除。

### 无机型截图

1. 正确判定无精确机型后进入最终截图阶段。
2. 应用 80% 临时比例并等待页面重排。
3. 定位首个可见商品卡，使搜索框中的当前搜索词与至少一个不匹配商品名称同屏。
4. 条件满足后立即截图，不再执行第二次滚动。

### 详情页截图

1. 价格和实际配置验证完成后应用 80% 临时比例。
2. 只定位一次，使产品标题、有效价格、实际选中颜色和实际选中容量同屏。
3. 条件满足后立即截图；截图结束、失败或取消后恢复原比例。

## 天猫处理规则

1. 不修改天猫登录、搜索、商品匹配、配置选择或价格读取规则。
2. 仅在最终状态复核与截图阶段应用 80% 临时比例。
3. 详情页要求标题、价格、颜色和容量同屏；无机型页要求搜索词与商品名称同屏。
4. 截图结束、失败或取消后恢复原比例。

## 状态与恢复

- 站点适配器保存应用 80% 前的网页比例。
- 正式截图运行器在成功、失败和异常路径均调用恢复钩子。
- JD 回退配置的语义检查点保存实际容量、颜色和 SKU，后续复核不得重新按不可用的基础表配置判定失败。

## 自动测试

- JD 最终截图固定应用 80%，不再应用 90%。
- JD 无机型结果页在 80% 下同时校验搜索框和商品名称。
- JD 精确容量可用时仍使用原有精确配置逻辑。
- JD 目标容量不可用、同机型存在可用配置时，选择实际可用配置并读取划线价 `2999`。
- JD 不得从其他机型或不可验证价格节点取价。
- Tmall 的有报价与无机型截图均应用 80%，并在结束后恢复。
- 荣耀官网回归结果保持不变。

## 人工验收

1. Power2 京东列写入 `2999`，截图可见 Power2 标题、`2999`、实际颜色和实际容量。
2. 畅玩80京东价格为“无”，截图可见搜索框中的畅玩80搜索词及下方不匹配商品名称。
3. 天猫最终截图画面在 80% 下包含对应必需信息。
4. 荣耀官网价格与截图和 `.40` 保持一致。
