# 报价决策智能体优化需求记录

记录日期：2026-09-13

状态：用户已确认本轮需求及两张界面方向。先记录，暂不开发；用户接下来讨论稽核审查智能体，后续按确认范围安排程序优化。

## 一、定位与进入流程

现有程序完成渠道取价、截图、最低有效价比较，并生成报价工作簿后，产品经理在“报价决策智能体”中选择商品，进入单品辅助报价页面，补齐原先需要手工填写的数据，查看提示、调整报价，再写回本次已生成的报价表。

页面主标题确定为“报价决策智能辅助”。侧栏产品名称继续为“报价决策智能体”。右侧栏目确定为“智能报价提示”，不使用“实时规则检查”。

保持用户接受的简洁双栏布局：上方商品与渠道价格，左侧产品经理填写，右侧智能报价提示，下方报价表待写入预览与操作按钮。用户已明确否定较复杂的增强版，不加入该版本的额外可视化或复杂面板。

## 二、填写内容与写回

产品经理可填写和调整以下五项，调整后实时更新比较结果和提示：

| 内容 | 已讨论样表列 |
| --- | --- |
| 当月铺货结算报价 | K |
| 终端公司采购价 | L |
| 全国采购系统均价（规则中称全国比价系统均价） | M |
| 渠道买断价 | P |
| 分销零售价 | Q |

报价月份来自本次任务，不能固定写成8月或9月。报价说明对应 AO 备注，并提供关联依据附件的入口。

保存时写回本次已经形成的工作簿中对应商品的手工填写部分，保留原有自动取价、截图关联、公式及其他自动生成内容。下方提供待写入内容预览。正式开发须核对实际工作簿模板与商品定位，不能仅凭界面示例固定列号或行号。

未通过规则可以保存草稿，但不能标记为已通过或确认报送；优福包属性待确认时同样不能确认本品报价。保存草稿与最终确认须区分状态。

## 三、已确认的报价原则

1. 当月报价不得高于往期报价、分销零售价、一级库价格及有效官方零售价，包括品牌官网、京东自营及官方旗舰店、天猫官方旗舰店。比较价格必须对应有效商品规格与渠道；缺失信息不能展示为通过。
2. 报送终端必须一级库在库。
3. 手机铺货结算报价不得超过终端公司采购价的 104.5%，即加价率不得超过 4.5%。采用精确数值判断，不能因显示百分比四舍五入而放行超限报价。
4. 终端公司采购价不得高于全国比价系统均价。这是“采购价与均价”的比较，不是要求当月报价直接低于全国均价。
5. 原则上自首次报价起，每6个月下调5%，12个月下调10%。无法调价时，需上游厂家无法下调价格说明、原材料涨价趋势说明等合理依据，记录在 AO 备注并关联材料。计时起点是首次报价，不是上市日期或入库日期。
6. 入总部一级库时间超过14个月时，先提示确认是否属于“优福包”。仅在确认属于优福包后正式列入“不报价”；确认不属于时继续其他报价校验。不能仅因超过14个月自动列入不报价。
7. 渠道买断价需填写、展示和写回，目前没有确认其构成独立硬性报价上限，不自行增加该规则。

## 四、智能辅助展示

- 展示三渠道有效价格、来源及查看取价证据入口。
- 对每项规则展示检查项、当前比较和结果，并实时响应输入调整。
- 展示当前可计算的报价上限、产生该上限的约束，以及需要下调的金额。报价上限不能代替库存资格、优福包属性、调价依据等其他判断；其他规则未通过或信息不全时不能宣称整体通过。
- 展示首次报价时间和入库时间。
- 入库超过14个月的商品在右栏原有区域展示优福包确认提示，提供“是，列入不报价”“否，继续报价校验”两个操作。
- 不报价商品保留记录与处理原因，便于后续稽核追溯；具体与最终工作簿的状态表达在开发时核对模板。

## 六、实现前需要核对的规则细节

以下细节仍未形成最终业务定义，本次记录不擅自确定，也不影响先继续讨论稽核需求：

- 往期报价取上一期还是所有往期最低值，以及历史数据来源。
- 6个月、12个月调价的基准价格、超过12个月后的计算办法，以及例外依据的确认机制。
- 早期讨论提过多形态产品5%上限；本轮明确规范聚焦手机4.5%，多形态分类与规则适用需核实后再实现。
- 一级库价格、库存状态、首次报价时间和入库时间的实际数据字段与缺失处理。
- 草稿写回、确认报价、不报价状态在正式工作簿中的具体表达及附件保存关联方式。

实施范围以已确认规则和现有程序为基础，保留现有 Mac 取价、截图与报价生成流程；本记录本身不改变程序行为。
