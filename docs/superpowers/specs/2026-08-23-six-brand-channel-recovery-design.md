# 六品牌三渠道恢复设计

## 目标

恢复荣耀、小米、OPPO、vivo、华为、苹果六个品牌的官网、天猫和京东任务，同时禁止对已经验收的品牌流程做无边界的全局放宽。

## 已确认根因

1. 官网不是同一种失败：荣耀、vivo、苹果本轮成功；OPPO 的无精确机型证据读取了错误搜索节点；小米已搜索但未识别 REDMI R70 5G 商品卡；华为在首页搜索框识别阶段失败。
2. 天猫目前只有一套荣耀旧版店铺模板。vivo、OPPO、华为、苹果在店铺身份或搜索表单校验阶段被拒绝，小米已提交搜索但无报价截图被系统截图环境拒绝。
3. 京东目前只有一套荣耀店铺模板。vivo、OPPO、华为在店铺身份校验前失败，小米已提交搜索但未进入详情，苹果已进入详情但新详情页 SKU 元素未被识别。
4. 荣耀京东已完成搜索、详情和取价，截图被 macOS 窗口身份校验拒绝，并非网页四项证据不完整。

## 设计原则

- 逐站冻结：官网先恢复并冻结，天猫其次，京东最后。
- 稳定品牌隔离：官网修改仅进入 OPPO、小米、华为适配器；荣耀、vivo、苹果只运行回归测试。
- 模板分层：天猫和京东将“店铺身份与搜索入口”按品牌/页面模板配置，详情页的价格、配置和截图能力继续共用。
- 语义优先：店铺身份允许经过规范化后的品牌官方店名称等价匹配，但仍必须同时满足批准域名和批准店铺入口，不能只凭模糊文字放行。
- 截图分层：网页四项语义证据与 macOS 原生窗口定位分别校验；窗口标题差异不能否定已经验证的网页证据，但仍只允许唯一的当前 Chrome 窗口。
- 可诊断：每个任务保存 entry、search、result、detail、configuration、price、capture 七阶段状态。

## 验收顺序

1. 官网六品牌契约与回归矩阵通过。
2. 天猫六品牌入口/搜索契约通过，并完成真实单品牌测试。
3. 京东六品牌入口/搜索/详情契约通过，并完成真实单品牌测试。
4. 七行基础表端到端测试，输出表与报告数量一致，不支持的中兴行保持“不支持”。
