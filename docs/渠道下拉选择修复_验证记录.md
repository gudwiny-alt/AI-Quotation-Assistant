# 渠道下拉选择修复

基线：5050281。修复“补充修正渠道取价”弹窗的官网／天猫／京东列表能展开但鼠标无法选择的问题。

原因：父弹窗使用 Tk modal grab，另一个 Toplevel 中的下拉列表收不到原生鼠标事件。原代码通过真实 Quartz 鼠标操作复现：点击天猫后仍为官网。临时把 grab 转给下拉列表后可正确选中天猫，确认输入路由问题。

修复仅修改 desktop_controls.py：已有模态输入锁定时，下拉框暂时接管输入；macOS 采用弹出菜单式 grab，支持点击外部取消。选择、Esc、点击外部和关闭父窗口后，正确恢复原窗口的输入状态；不会覆盖后来由其他窗口取得的 grab。

验证：

- 新增原生鼠标测试，修复前渠道切换失败，修复后通过。
- 官网、天猫、京东逐个实际点击，价格、来源链接、图片显示与所选渠道同步；选择本身不修改工作簿。
- 点击外部、Esc、关闭弹窗后的输入恢复，以及超过可见行数的下拉列表真实滚轮测试通过。
- 受影响控件、渠道弹窗保存的最终测试：29 passed，13.50 秒。
- 完整原生界面测试：63 passed，4 failed。四项为当前 WindowServer 把大窗口高度限制为843像素导致的布局断言；使用5050281的原控件复跑，同样4项失败，确认不由本次修复引入。未改动这些布局或放宽测试断言。
- 独立只读代码审查未发现新的回退问题。Ruff、git diff --check 通过。

App 重新打包；交付过程检查签名、--help启动以及包含当前控件和上一版10个业务模块的包内字节码与源码一致性，结果见 bundle-verification.json。

未修改报价规则、网站取价、截图或Excel写回服务，未操作用户实际报价表。本轮没有重新运行正式网站采集，也没有实施尚在讨论的规则配置功能。

使用：退出旧版后打开新App，加载原报价表。进入“补充修正渠道取价”，点击修正渠道并选择所需渠道即可；三项均已显示时无需滚动列表。检查对应截图、价格和链接后保存。
