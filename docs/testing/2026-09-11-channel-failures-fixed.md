# 9 月 11 日三条渠道失败修复与真实复测

基线：953a02b，分支 codex/mac-170-ui-refresh。

## 已证实的原因与修复

### 华为官网：等待新标签页地址提交

对畅享 90 Pro Max 进行真实复现，调用栈停在 `_wait_for_portal_detail`，实际已选中正确的 portal 卡片。点击后 Chrome 新页面的 `url` 连续数次为空字符串，约 1 秒后变成批准的 VMALL 数字商品详情地址。旧代码仅等待 `about:blank`，空字符串被立即判为非法详情。

将空字符串纳入原有最多 10 秒的有界等待；地址提交后仍须通过原有域名及数字商品 URL 校验。非法页面、多弹窗和超时仍拒绝并清理。

这纠正了此前只根据失败截图与旧式 result_region_count 推断“未识别卡片”的判断。旧诊断中的零值不能代表 React 商品卡没有被识别。

### 苹果天猫：空商品卡与明确优惠前价

真实搜索列表有 48 张可见 `dl.item`，前 47 张有正常标题，包含精确 iPhone 17；末尾一张只有数字 data-id，无文本、无子元素。旧代码强制所有可见卡片有唯一标题，空卡阻断了已有精确商品。

只跳过符合该结构的空占位；必须仍有正常精确型号才能继续。无匹配且有空占位时仍返回技术错误，不推断“无此型号”。非空异常卡、未知链接、型号变体仍保留检查。

进入正确 SKU 后，页面当前显示“平台加补后 5999”和“优惠前 6799”。苹果旧锁价路径没有接入已有权威优惠前价识别，导致高亮促销文案无法解析。将苹果接入原有当前 SKU 权威价格读取，沿用 2026-08-08 与 2026-08-29 设计：明确优惠前价优先，补贴金额不得替代报价。隐藏或 SKU 容器外的优惠前价仍拒绝。

### 荣耀京东：根据完整目标规格消除多颜色 SKU 歧义

真实列表同型号有三个 SKU：绒黑色、雪域白、天青釉，均显示 16+512。原方法只检查型号，三个不同链接被认定为歧义。

现代列表存在多个商品 URL 时，根据唯一 `.jDesc a` 标题中的型号、RAM/存储对及完整颜色选出唯一 URL。此次唯一目标为 `100213070059`。没有明确配置、多个同配置 URL、标题结构未知、单卡链接冲突仍停止；不回退到唯一有货但错色的商品。详情中的卖家、选中规格、SKU 与价格继续原有校验；不使用搜索页价或历史价。

### 界面黑线

侧边栏设置了 Tk highlightthickness=1，但没有指定焦点色，取得焦点时出现默认黑色边框。移除原生焦点边框，改用静态浅色右侧分隔线，顶部不再描边。
