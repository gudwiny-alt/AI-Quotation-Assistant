# Mac 未完成任务恢复（2026.09.18.171）

## 使用方式

1. 重启应用后进入「任务记录」，选择原批次，点击「恢复未完成任务」。数据准备页也提供进入任务记录的快捷入口。
2. 恢复原批次、原商品及渠道范围，不需要重新填写本次输入表单。「开始自动报价」仍然创建新批次。
3. 如果只需要已有结果，点击「仅导出已有成果」，不会启动浏览器或要求截图权限。
4. 恢复过程中可点击「停止并导出」。系统在当前操作安全结束后停止后续采集并导出；不是立即强制结束进程。

## 数据与兼容性

- 新批次在第一次采集前，将完整任务范围及恢复上下文与批次记录一起持久化。
- 已完成任务、已保存价格和截图继续使用，不重新采集。中断、暂停、等待验证及未执行任务可以恢复。
- 失败任务沿用原有重试次数。不可重试或已耗尽次数的失败任务保持原状；并非固定跳过 82 条。
- 恢复前验证输入文件指纹、商品快照、任务范围和截图证据。校验失败时不启动采集；可还原文件后恢复，或仅导出已有成果并查看报告中的校验问题。
- 每次恢复或导出在原输出目录下创建独立的「恢复成果-时间-标识」目录。原报价表、处理报告及证据文件保留。
- 旧版批次若未保存完整执行范围，仅恢复数据库里已经登记的任务，不推测未登记的后续渠道。完整范围恢复从此版本创建的批次起生效。
- 数据库仅增加恢复上下文表，保留原表与历史数据。兼容检查针对真实数据库的临时副本进行，原数据库只读。

- 调度测试覆盖 82 条已耗尽失败不会重跑、剩余一次技术重试不重置、当前渠道范围和全局登录等待约束。
- 本机 Tk 界面测试 34 项通过，并检查任务记录窗口的恢复入口、旧成果显示和停止按钮布局。
- 全量非 UI 回归运行：3221 项通过、2 项失败。其中登录等待问题已修正；另一个子进程测试缺少当前工作树的 `PYTHONPATH`。两个失败项与恢复相关测试使用当前代码、正确路径再次执行，最终 145 项全部通过（51.36 秒）。复验中另消除一个旧暂停测试的计时竞争：在首次尝试开始后才启动暂停计时，避免机器忙时变成「开始前暂停」。
- 安装包 102 个应用模块逐一与当前源码比对一致；ARM64 可执行文件、内嵌依赖、临时签名验证通过。不包含本机 AI 设置、API Key、业务任务数据库或 `.env` 文件。

## 运行边界

沿用现有 Mac 版本的系统、芯片、Chrome 及权限要求；本次没有扩展 Intel 或旧版 macOS 兼容范围。等待验证需要人员在浏览器完成登录后继续。故障恢复依赖本地数据库、原输入和已保存证据仍然可用。
