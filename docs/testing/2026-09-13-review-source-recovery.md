# 报价决策及截图稽核修复验证

基线：87e37d9。范围为生成报价表之后的本地数据恢复、决策提示及截图初核。未修改取价适配器、浏览器控制、截图采集流程和 Excel 核心生成逻辑。

## 问题与改动

- 原来的 `from_workbook` 只恢复商品和手填单元格，没有读取 AI/ AJ/ AK 渠道价格、AL/ AM/ AN 内嵌图片，导致价格空白、截图误报缺失。现在按工作表行、物料编码和渠道恢复。
- 若本机存在对应批次，核对月份、输出位置、源快照身份，再将内嵌图片与原始截图生成的缩略图作 SHA256 精确比对。只有图片及价格一致才恢复原任务来源、无机型结果及高清原图。完整图片集合确认该批次后，保留同批次的明确失败记录。匹配不充分时使用表内图片，不猜测来源。
- 按唯一物料编码关联营销表：自动提供在库资格、入库时间、短机型名及规格。建议零售价区间按用户要求取上端；倒置、无界或无法识别的区间不自动放行。历史报价读取基础表已提供的全部往期月份，首次报价日期保持独立。
- 当前决策仅按手机 4.5% 精确十进制规则计算。每条智能报价提示支持点击/回车查看依据；适用历史范围可填写依据和操作人后确认。自动来源字段锁定，仍可填写首次报价日期依据。
- 截图通过 macOS Vision 在后台本地识别。按文件内容摘要缓存，不联网、不重新取价。检查目标机型、规格文字、价格及来源文字、图片尺寸与关键文字可读性。优惠/补贴、多口径、识别不充分保留具体复核原因；这项检查不是对网页交易条件的全面证明。
- 无匹配机型只有获得精确任务来源后才按搜索证据处理，不要求它包含目标商品售价。空价格不能自行推断为无机型。缺图、识别中、需复核分别呈现。
- 稽核依据区域可以滚动，识别结束自动刷新并保留选择。

## 验证

- 新的来源恢复测试先失败，再修复通过；截图内容规则、错误状态、无机型分支及精确图片来源匹配有独立测试。
- 非 UI 全量：3086 项通过，1 项因沙盒禁止绑定本地测试端口而未运行成功；该项在允许本地端口的环境单独复测通过。
- 最后一次相关服务测试：43 项通过；原生 UI 全量：60 项通过。包括三个只读来源字段、规则详情打开、导航、保存白名单、各窗口尺寸及滚动。
- Ruff 和 `git diff --check` 通过。独立 PyInstaller App 构建成功，完成签名完整性检查与命令行启动检查。
- 实际已有 6 款商品、18 个渠道任务回放恢复 17 张截图。截图内容共 72 项：25 通过、16 不适用、27 待复核、4 待补充；4 个待补充项对应同一条真正没有截图的失败渠道，而非 4 个失败任务。
